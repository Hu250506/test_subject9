## 3. 계산

```text
HTTP 응답시간 감소율(동기 MISS 대비 비동기 MISS 접수)
  = (24.16 - 9.25) / 24.16 × 100 = 61.71%

전체 결과 확인시간 차이(MISS)
  = 66.58 - 24.16 = 42.42 ms (비동기 최종 확인이 더 느림)

동기 캐시 HIT의 HTTP 응답 감소율(동기 MISS 대비)
  = (24.16 - 2.08) / 24.16 × 100 = 91.39%
```

## 4. 캐시 비교

| 경로 | 캐시 | HTTP 응답(ms) | 추론시간(ms) | 메모 |
|---|---|---:|---:|---|
| 동기 | MISS | 24.16 | 18.28 | 모델 실제 추론 |
| 동기 | HIT | 2.08 | null | 모델 추론 생략 |
| 비동기 | MISS | 9.25 (접수) | 17.85 | 완료 확인은 별도 기록(66.58) |
| 비동기 | HIT | 9.05 (접수) | null | 완료 확인은 별도 기록(67.94) |

## 5. 해석

- 비동기 접수 HTTP 응답(9.25ms)은 동기 MISS 응답(24.16ms)보다 61.71% 짧았다. 이는 모델 추론이 빨라졌다는 뜻이 아니라, 접수와 실제 처리를 분리한 효과다. 비동기에서도 추론시간(17.85ms)은 동기(18.28ms)와 비슷하다.
- 비동기 최종 확인(66.58ms)은 동기(24.16ms)보다 길었다. 큐 전달, Worker 처리, 상태 조회 간격(0.05초)이 포함되기 때문이다.
- 동기 Cache HIT는 HTTP 응답이 2.08ms로 MISS보다 크게 짧았다. 추론시간이 `null`인 것은 추론을 생략했다는 뜻이며, 0ms라는 뜻이 아니다.
- 비동기 HIT의 접수(9.05ms)와 최종 확인(67.94ms)은 MISS(9.25ms, 66.58ms)와 비슷했다. 비동기 경로는 캐시 HIT여도 접수, 큐, 상태 조회 단계를 거치므로 이 측정에서는 최종 확인시간이 줄지 않았다. 스크립트의 조회 간격(0.05초) 영향도 포함되어 있어 그 이상의 원인은 확인하지 않았다.
- 처음 한 번의 모델 로딩 시간은 워밍업(`run_id=0`)으로 구분했다. Worker가 모델을 처음 쓰는 작업은 약 2초(DB 이력의 job 1, 2, 8)로 기록되어 있다.

## 7. 한계

- 이미지 1장, 조건별 5회 측정이며 통계적 일반화는 하지 않는다.
- 측정 스크립트(0.05초 간격 상태 조회)와 브라우저 화면(1초 간격)의 비동기 완료시간은 다르다.
