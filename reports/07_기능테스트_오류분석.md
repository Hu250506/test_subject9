## 3. 오류 이력

| 오류 ID | 현상                                     | 원인 확인                                                                                              | 조치                                       | 재검증                                                                          | 결과                   |
| ----- | -------------------------------------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------- | ---------------------------------------------------------------------------- | -------------------- |
| E-01  | job 8이 `queued`로 유지                    | 의도적으로 Worker 터미널을 종료한 상태                                                                           | 제공 명령으로 Worker 재실행                       | 같은 `job_id=8` 재조회                                                            | `done` 확인 (이번 1회 결과) |
| E-02  | Docker 실행 시 `web`이 `unhealthy`로 계속 재시작 | 로그: `cannot import name 'ImageJob' from 'ai.models'`. `ai/models.py` 저장이 안 된 채 빌드됨                 | 파일 저장 후 `docker compose up -d --build`   | `web` healthy, `/health` 200                                                 | 해결                   |
| E-03  | 동기 API에서 캐시 HIT가 발생하지 않음               | 같은 파일을 2회 올려도 `cache_hit false`. `ai/router_sync.py`가 01 버전(`classify_image_bytes` 직접 호출)으로 남아 있었음 | 02 문서 15장의 `classify_with_cache` 버전으로 교체 | 같은 파일 2회 요청에서 cache_hit False → True 확인, timings.csv 재측정 (동기 HIT 중앙값 2.08ms) | 해결                   |
| E-04  | `/vision/sync/` 접속 시 500               | 로그: `TemplateAssertionError: block 'title' defined twice`. `templates/base.html`에 같은 내용이 중복됨       | `base.html`을 02 문서 내용으로 교체 후 재빌드         | 화면 정상 로드                                                                     | 해결                   |
| E-05  | `docker` 명령을 찾을 수 없음                   | Docker Desktop의 WSL 연동이 꺼진 상태                                                                      | Docker Desktop 실행, WSL Integration 활성화   | `docker --version` 출력, `image_jobs` 조회 성공                                    | 해결                   |

- E-02, E-04는 02 문서를 따라 Docker 전체 실행으로 시험하던 단계에서 발생했다. 이후 평가가이드 구조(FastAPI·Celery는 WSL, Redis·PostgreSQL은 Docker)로 전환해 이 단계 이후의 테스트를 진행했다.
- `MODEL_PATH`가 원본 모델을 가리키는 오류는 발생하지 않았다(`model_id`가 처음부터 `artifacts/beans_resnet18`로 출력됨).
